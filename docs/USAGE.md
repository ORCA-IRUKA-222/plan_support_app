# 使い方 — 企画を1本通す

はじめて使うときは、この順にたどれば1本の企画が仕上がります。
迷ったらダッシュボードの「次にやること」だけを見てください。

## 0. 企画を作る

サイドバー上部のセレクトから「+ 新しい企画…」。名前は仮でかまいません。
ダッシュボードで**提出先**（例: ◯◯社 インターン課題）を入れておきます。
収益構造・IP・時間軸の前提が変わるので、これは早めに決めるほど後が楽です。

## 1. ネタ帳（段階0）

思いついたら1行でも書きます。本文に `#タグ` を書くと自動で拾われます。

- **この企画 / 共通ネタ帳** を切り替えられます。まだどの企画に使うか決まらないものは共通へ。
- 出所フィルタを選んでからメモすると、その出所が付いた状態で保存されます。
- 良さそうなメモは「種へ」で段階1に送れます。

> ゲート: メモ10件以上、かつ直近7日のメモがある（＝ネタ帳が枯れていない）

## 2. 種出し（段階1）

タブが3つあります。**必ず「出す → 判定する → まとめる」の順**で進みます。

### 1. 出す

出所7分類のチップを切り替えながら、質を問わず書き出します。
発想が止まったら「別の問い」を押すと、その出所に対応した問いが切り替わります。

人に話したくなる種には ★ を付けます。

> ゲート: 30個以上、★が3つ以上、4分類以上から出した

### 2. 判定する

4判定（一行性・未既視感・反応の質・自分の必然性）を1〜4で採点します。
点数そのものより、**どこが弱いか**を見るための道具です。合計順に並び替わります。

### 3. まとめる（KJ法）

似た種を選んで「束にして名前を付ける」。**先にカテゴリを決めないこと**。
名前を付ける瞬間に出てくる言葉が、そのままキャッチコピーの原型になります。

## 3. 核を決める（段階2）

ここを飛ばして企画書に行かないでください。多くの企画書が失敗する原因です。

- **核の一行**: 60字以内。「★の種から選ぶ」で段階1の種から持ってこられます。
- **3層モデル**: 核（失うと別物になる） / 骨格（核を成立させる仕組み） / 演出（差し替え可能）。
  迷ったら演出を消してみて、それでも面白ければ核は生きています。
- **4判定**: 4つすべてが3以上で通過。
- **人に話した反応**: 「なるほど」ではなく「それどうなるの?」が出たかを記録します。

核が決まらないときは「思考ツール」へ。状況別の使い分け表が出ています。

## 4. 骨格を検証（段階3）

- **コアループ**: 入力 → 変化 → 報酬 → 次の入力。30秒単位で書けるか。
- **ターゲット**: 属性ではなく行動で。「中高生」ではなく「授業でPythonを触ったが退屈している中高生」。
- **収益**: 提出先の収益構造に乗っているか。「操作の快感」と「課金動機」がつながると強い企画です。
- **実現性**: プロトタイプがあれば最強の回答になります。
- **引き算テスト**: 要素を消してみる。消しても成立するものは核ではありません。
- **一般化テスト**: 題材を差し替えても成立するなら、それは演出です。
- **残す弱点はひとつ**: 反論を全部潰さないこと。認めたうえで「それでもやる理由」を書きます。
- **5つの質問**: 審査側が最初に見る順番です。

## 5. 企画書（段階4）

まず「フレームワーク」で 3C / SWOT / 6W2H / CTPT を埋めておくと、
企画書画面の**「フレームワークから下書き」**で各セクションに文章が入ります。

- **書く**: 6つの必須セクション + 弱点 + 補足。各セクションにヒントが付いています。
- **プレビュー**: 実際の見え方。
- **仕上げチェック**: 文章の3ポイントと見やすさの3法則、配色（ベース70/メイン25/アクセント5）、
  陥りやすい罠5つ。

書き出しは **Markdown** / **HTML** / **印刷（→PDF）**。HTML はここで選んだ配色とフォントが反映されます。

> 冒頭の順番に注意。背景説明から始めず、一番面白い瞬間から始めて根拠は後ろに置きます。

## 6. 発表

- **冒頭30秒のフック**を書くと、スライドの2枚目に入ります。
- 「発表を始める」で全画面のスライドモード。
  矢印キー / スペース / 画面タップで送り、Esc で閉じます。
- 持ち時間を過ぎるとタイマーが赤くなります。
- **想定質問**は、認めた弱点が上部に表示された状態で書けます。

## 端末をまたぐ

「設定・同期」で、PC とスマホの両方に**同じアクセストークン**を入れます。
1台目は Gist ID を空のまま「いま同期する」を押すと Gist が作られ、ID が表示されます。
2台目にはその ID を入れてください。詳しい手順は README の「端末間の同期」にあります。

以降は起動時・画面復帰時・変更の30秒後・表示中は60秒ごとに自動で揃います。
すぐ揃えたいときは右上の「⟳ 同期」を押します。

GitHub を使いたくない場合は、同じ画面の**バックアップ**から JSON を書き出して
別端末で読み込んでください。
