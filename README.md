# 企画伴走 — 立案から企画書発表までをサポートするアプリ

種出しから核の一行化、骨格の検証、企画書、発表リハーサルまでを**段階（フェーズ）とゲート**で進めるアプリです。
PC のブラウザと Android スマホの両方で使えて、同じ内容が同期されます。

- **ローカルファースト**: データはまず端末内に保存され、通信が切れても入力を続けられます。
  ただし **PC を切った状態でスマホから起動できるのは APK 版だけ**です
  （LAN 経由の PWA はブラウザの制約で不可。[理由](docs/PWA-vs-APK.md)）。
- **同期はあとから**: 自分で立てた同期サーバーを登録すると、差分だけを送受信して端末間で揃えます。
- **PWA / APK の両対応**: ブラウザからそのままインストールでき、Capacitor で APK も作れます。

---

## 1. できること

### 進行（5段階 + ゲート）

企画書作りは「書く作業」ではなく「収束させる作業」です。段階ごとに、次へ進んでいい条件（ゲート）を
決めておくと手戻りが減ります。アプリは各ゲートを**できる範囲で自動判定**し、残りをチェックリストにします。

| 段階 | 画面 | やること | 次へ進む条件 |
|---|---|---|---|
| 0. 素材ストック | ネタ帳 | 遊んだもの・違和感・数字をメモに溜める | ネタ帳が枯れていない |
| 1. 種を出す | 種出し | 発散。質を問わず30〜50個 | 人に話したくなる種が3つ以上 |
| 2. 核を決める | 核を決める | 1行に圧縮。3層モデルの「核」を確定 | 一文で言えて、聞いた人が絵を想像できる |
| 3. 骨格を検証 | 骨格を検証 | コアループ・ターゲット・収益・実現性 | 引き算テストと一般化テストを通過 |
| 4. 書面化 | 企画書 | 構成・図・数値・演出 | 冒頭30秒で「面白そう」と思わせられる |

例えば「種が30個以上あるか」「★が3つ以上あるか」「出所7分類のうち4種類以上から出したか」
「核が60字以内か」「4判定すべてが3以上か」「目的に数値が入っているか」は、
入力内容から自動で判定されます。ダッシュボードには**次にやること**が1つだけ表示されます。

### 道具

- **思考ツール**: マインドマップ（第1階層を8軸に固定）／マンダラート／SCAMPER／逆転発想・問題逆転／
  三角メモ／体験の時間割／アナロジー移植。KJ法は「種出し」画面の中にあります。
- **フレームワーク**: 3C分析／SWOT分析／6W2H／CTPT／書く前に潰す5つの質問。
- **企画書**: 6つの必須セクション + 弱点セクション。フレームワークに書いた内容から**下書きを自動生成**できます。
  Markdown / HTML の書き出しと、ブラウザ印刷からの PDF 化に対応。
- **発表**: 企画書からスライドを組み立て、冒頭30秒のフック・リハーサル用タイマー・想定質問を扱います。

### 設計上の意図

- マインドマップは自由に枝を伸ばすより**第1階層を8軸に固定**したほうが機能します。
  第2階層が空の軸と、まったく手つかずの軸は**弱点として赤く表示**されます。
- 「操作」と「収益」のように、**枝から枝への線**を引けます。
- KJ法は先にカテゴリを決めず、集めてから名前を付ける順番でしか操作できません。
- 弱点は1つ残して「それでもやる理由」を書く欄があります。全部潰した企画書は安全ですが面白くないためです。

## 2. 使い始める

### 準備するもの

**Node.js 22 以上**だけです（同期サーバーが `node:sqlite` を使うため 22 以上が必要）。
https://nodejs.org/ja から LTS 版を入れてください。入ったかどうかは次で確認できます。

```bash
node -v      # v22.x.x 以上ならOK
```

### コードを PC に持ってくる

コマンドは**このリポジトリのフォルダの中**（`package.json` がある場所）で実行します。
まだ PC にコードがなければ、どちらかの方法で取得してください。

```bash
# 方法A: git がある場合（あとで更新するのが楽）
git clone https://github.com/ORCA-IRUKA-222/plan_support_app.git
cd plan_support_app
```

方法B: git を使わない場合は、GitHub のリポジトリ画面で緑の **Code** ボタン →
**Download ZIP**。展開してできたフォルダに移動します。

```bash
cd C:\Users\<ユーザー名>\Downloads\plan_support_app-main   # Windows の例
cd ~/Downloads/plan_support_app-main                          # macOS の例
```

正しい場所にいるかは、`package.json` が見えるかで確認できます。

```bash
dir package.json     # Windows (PowerShell / コマンドプロンプト)
ls package.json      # macOS / Linux
```

### 起動する

```bash
npm install          # 初回だけ。数分かかります
npm run build
npm run server       # http://localhost:8787 で画面と同期APIの両方を配信
```

ブラウザで http://localhost:8787 を開けばアプリが出ます。
**ターミナルは開いたままにしてください**（閉じるとサーバーが止まります）。
止めるときは `Ctrl` + `C`。2回目以降は `npm run server` だけで起動します。

Chrome や Edge のアドレスバーに出る「インストール」からアプリとして入れられます。

> 開発中の画面を触りたいときは `npm run dev`（http://localhost:5173 、保存すると即反映）。
> ただしスマホと同期して使うのは `npm run server` のほうです。

### Android スマホで使う

2つの入れ方があります。違いは [docs/PWA-vs-APK.md](docs/PWA-vs-APK.md) にまとめました。
ざっくり言うと **どちらもホーム画面のアイコンから全画面で開く点は同じ**で、
違うのは配り方（PWA はサーバー経由、APK はファイルを直接インストール）です。

**方法A: PWA としてインストール（すぐできる・普段使いはこちらで十分）**

「同期サーバーを立てる」といっても、**追加の作業はありません**。
`npm run server` が同期サーバーそのもので、最初から同じ Wi-Fi の他の端末から
つながる状態（`0.0.0.0` で待ち受け）になっています。やることは次の4つだけです。

**① PC の IP アドレスを調べる**

```bash
ipconfig                      # Windows → 「IPv4 アドレス」の行を見る
ipconfig getifaddr en0        # macOS (Wi-Fi)
hostname -I                   # Linux
```

`192.168.` や `10.` で始まる番号が出ます（例: `192.168.1.10`）。

**② PC で `npm run server` を動かしておく**

初回起動時に Windows なら「ファイアウォールがブロックしました」と出ることがあります。
その場合は **「プライベート ネットワーク」にチェックを入れて「アクセスを許可する」**
を押してください。ここを拒否するとスマホからつながりません。

**③ スマホの Chrome で開く**

スマホを **PC と同じ Wi-Fi** につないでから、`http://192.168.1.10:8787`
（①で調べた番号）を開きます。アプリの画面が出れば成功です。
メニューの「⋮」→「アプリをインストール」でホーム画面に追加できます。

**④ PC とスマホの両方で同期設定を入れる**

どちらの端末でも「設定・同期」を開き、**同じ内容**を入れます。

| 項目 | 入れる値 |
|---|---|
| 同期サーバーの URL | `http://192.168.1.10:8787`（①の番号。PC も同じでOK） |
| 合言葉 | 8文字以上の好きな文字列。**両方の端末で完全に同じもの** |

これで両端末の内容が揃います。アプリを直したときは PC で `npm run build` するだけで
スマホにも反映されます。

> **この方法では PC を切るとスマホから開けません。** オフライン起動に必要な
> Service Worker は HTTPS か localhost でしか動かず、`http://192.168.x.x` は
> どちらでもないためです（アプリの「設定・同期」画面の先頭に可否が出ます）。
> 外出先でも使いたい場合は下の**方法B（APK）**を使ってください。

> つながらないときは、まず PC 自身のブラウザで `http://192.168.1.10:8787`
> （`localhost` ではなく①の番号）を開いてみてください。
> ここで開けなければファイアウォール、開けるのにスマホから見えなければ
> Wi-Fi が別（スマホが 5GHz とゲスト用など）の可能性が高いです。

**方法B: APK を作る（PCを起動していない場所でも単独で使いたいとき）**

Capacitor で APK を生成します。JDK 21 と Android SDK が必要です。

> APK から LAN の同期サーバー（平文 HTTP）につなぐには2つの設定が要ります。
> どちらもビルド手順に組み込み済みなので、追加の作業は不要です。
> - `allowMixedContent: true`（`capacitor.config.ts`）
>   — アプリは `https://localhost` で動くため、`http://` 宛の通信が既定で遮断される
> - `android:usesCleartextTraffic="true"`（`scripts/configure-android.mjs` が付与）
>   — Android 9 以降は平文 HTTP が既定で遮断される
>
> どちらか欠けると、同期が必ず `Failed to fetch` で失敗します。

```bash
./scripts/build-apk.sh debug
# → app/android/app/build/outputs/apk/debug/app-debug.apk
```

Android SDK が手元にない場合は、GitHub Actions の **Android APK** ワークフローを
手動実行（Actions タブ → Android APK → Run workflow）すると、
実行結果の Artifacts から `kikaku-bansou-debug-apk` をダウンロードできます。
zip を展開すると `app-debug.apk` が入っているので、スマホに転送してタップすればインストールできます
（初回は「提供元不明のアプリ」の許可が必要です）。

> `app/android/` は `capacitor.config.ts` から再生成できるためリポジトリには含めていません。
> スクリプトが必要に応じて `npx cap add android` を実行します。

ビルド実績 (GitHub Actions, ubuntu-latest):
`app-debug.apk` 4.4MB / Gradle 2分7秒 / compileSdk 35 / minSdk 23 (Android 6.0 以降) /
アプリID `app.kikaku.bansou`。APK の中に `assets/public/` として画面一式が入るので、
インストール後はサーバーなしで単独起動できます。

## 3. 端末間の同期

### しくみ

すべてのデータは `id` と `updatedAt` を持つ**レコード**として保存されます。同期は1往復で完結します。

1. 前回の送信以降に手元で変わったレコードだけをサーバーへ送る（push）
2. サーバーの `cursor` 以降に他端末が変えたレコードを受け取る（pull）
3. 同じ `id` がぶつかったら **`updatedAt` が新しいほうを採用**（Last-Write-Wins）

同じ項目を2台で同時に編集すると、あとから保存したほうが残ります。
別々の項目（例: PCで企画書、スマホでネタ帳）を編集した場合は両方とも残ります。

細かい配慮:

- **カーソルは時計ではなく連番**です。端末の時計がずれていても取りこぼしません。
- 端末の時計が巻き戻っても、`updatedAt` はセッション内で**単調増加**します。
- push が LWW で負けた場合、サーバーは**勝ったほうのレコードを明示的に返します**。
  これがないと、時計の遅れた端末だけが古い内容を持ち続けてしまいます。
- 削除は墓標（`deleted: true`）として伝わるので、他端末で復活しません。
- 同期は「1企画1ツール」単位のレコードなので、マインドマップとネタ帳を別端末で同時に触っても衝突しません。

### サーバーを立てる

```bash
# 既定では app/dist（ビルド済み画面）も同じポートから配信します
npm run server
```

| 環境変数 | 既定値 | 説明 |
|---|---|---|
| `PORT` | `8787` | 待ち受けポート |
| `HOST` | `0.0.0.0` | 待ち受けアドレス |
| `DB_FILE` | `server/data/sync.sqlite` | SQLite ファイルの場所 |
| `WORKSPACE_KEYS` | （未設定） | 許可する合言葉をカンマ区切りで指定。未設定なら8文字以上の任意の文字列を受け付けます |
| `STATIC_DIR` | `app/dist` | 配信する静的ファイル。API だけにしたい場合は存在しないパスを指定 |

合言葉はサーバーに平文で保存されません（SHA-256 のハッシュをワークスペースIDとして使います）。
合言葉が違えば互いのデータは見えません。

### 端末側の設定

各端末で「設定・同期」を開き、**同期サーバーの URL**（例: `http://192.168.1.10:8787`）と
**合言葉**（全端末で同じ8文字以上の文字列）を入れます。
自動同期は、起動時・画面復帰時・変更の30秒後に走ります。
すぐ揃えたいときは画面右上の「⟳ 同期」を押します。

> 合言葉が1文字でも違うと**別々のワークスペース**として扱われ、内容は共有されません。
> 「つながっているのに何も出てこない」ときは、まず合言葉を疑ってください。

> **インターネット越しに使う場合**、この同期サーバーには合言葉以外の防御がありません。
> Tailscale などの VPN の内側に置くか、HTTPS のリバースプロキシを前段に立ててください。
> LAN の外に生で公開しないでください。

### サーバーを使わない同期

「設定・同期」の**バックアップ**から JSON を書き出し、別の端末で読み込めば移せます。

### データはどこにあるか / バックアップ

同じ内容が3か所に置かれます。1か所が消えても他から戻せます。

| 場所 | 実体 | 消えるとき |
|---|---|---|
| PC のブラウザ | localStorage | ブラウザの閲覧データ削除 |
| スマホ | localStorage（PWA）／アプリ内（APK） | アプリの削除、ストレージの消去 |
| 同期サーバー | `server/data/sync.sqlite` | そのファイルを消したとき |

**同期サーバーが実質のバックアップです。** 全端末の全レコードが入っているので、
スマホを機種変更しても、新しい端末に同じ合言葉を入れて同期すれば元に戻ります。
削除したものも墓標として90日間残るため、消しすぎた直後なら気づけます。

万一に備えるなら、次の2つのどちらかを習慣にしてください。

1. **JSON を書き出す** — 「設定・同期」→ バックアップ →「書き出す（JSON）」。
   ファイル1つで全企画が入ります。読み込みは同じ画面から（**現在の内容を置き換えます**）。
2. **sqlite ファイルをコピーする** — `server/data/sync.sqlite` を丸ごとコピー。
   サーバーを止めてからコピーすると確実です（`-wal` と `-shm` も一緒に）。

```bash
# サーバーを止めてから
cp -r server/data ~/backup/kikaku-$(date +%Y%m%d)
```

> 提出前など節目では JSON を書き出しておくと安心です。
> 同期の衝突解決は「あとから保存したほうが残る」方式なので、
> 2台で同じ項目を同時に編集した場合、片方の編集は残りません。
> 書き出した JSON があれば、その時点の状態に戻せます。

## 4. 開発

```bash
npm run dev          # 開発サーバー
npm run typecheck    # TypeScript の型チェック
npm test             # フロントエンド (vitest) + 同期サーバー (node:test)
npm run build        # 本番ビルド
npm run server       # 同期サーバー
npm run apk          # Android APK（要 Android SDK）
```

### 構成

```
app/                   フロントエンド (React 19 + TypeScript + Vite)
  src/domain/          型・知識ベース・既定値・ゲート判定
  src/store/           永続化・マージ・同期クライアント
  src/views/           画面（進行5段階 + 思考ツール + フレームワーク）
  src/lib/             ID・時刻・書き出し
server/                同期サーバー（依存パッケージ0件・node:sqlite）
scripts/build-apk.sh   APK ビルド
```

`app/src/domain/knowledge.ts` に、7分類・4判定・8軸・5つの質問・企画書の構成・
見やすさの法則などの**文言がすべて集約**されています。ここを直せばアプリ全体の表示が変わります。

## 6. 動作確認

```bash
npm test                              # 単体テスト（フロントエンド + 同期サーバー）

npm run build && npm run server &     # 通し確認の前にサーバーを起動
npm run e2e                           # 画面を一通り操作して壊れていないか確認
npm run e2e:sync                      # 2端末が同期サーバー越しに揃うか確認
```

`npm run e2e` は実ブラウザで24項目を操作し、各ステップ後に画面が空になっていないかを確認します
（型チェックでは見つからない実行時の壊れ方を拾うため）。
`npm run e2e:sync` は localStorage を分けた2つのブラウザプロファイルを「PC」と「スマホ」に見立てて、
実際に同期サーバー越しに内容が往復すること、別の合言葉には漏れないことを確認します。

初回はブラウザの取得が必要です。

```bash
npx playwright install chromium
```
